# Sankoch — 2.8.x-closeout P(-1): the 2.7.x encoders, the 2.8.x additions, the runtime seam

**Date:** 2026-10-13 (released as 2.8.6)
**Scope:** the surface accrued since the last audits (2.6.4 ZIP, 2.8.0 Brotli + reset seam):
- the 2.7.x encoders: the xz BT4 finder, 256 KB window and optimal parse; the zstd frame-global chain,
  cross-block window, DP optimal parse (levels 7–9) and chain cutoff;
- the 2.8.x additions: the Brotli decoder (2.8.0), the Brotli encoder (2.8.4), the PCLMULQDQ CRC-32
  fold (2.8.5), the runtime reset seam (2.8.0) and its lock;
- the DEFLATE 2.7.9 additions (fixed-vs-dynamic chooser, header pricer, `deflate_enc_flush`,
  `deflate_enc_reset_context`, `deflate_dec_produced`) and the Huffman builders behind them;
- the findings carried from 2.8.3 and the roadmap: Kraft completeness, the `_dyn_header_bits` bound,
  the fuzz harness exit codes, coverage reviewed as a matrix.

**Method:** six read-only adversarial reviews, one per surface (xz encoder, zstd encoder, Brotli
decoder, runtime seam, CRC fold, DEFLATE), each reproducing what it reported with a probe under
`build/review/<area>/`; then every finding verified again here before it was fixed, every fix tested,
and every new gate mutation-checked (the fix removed or weakened, the test seen to fail). External
research (RFC errata, reference-codec releases and CVEs since July) led to two reference
differentials, LZ4F and xz, that found more than the reviews did.
**Toolchain:** Cyrius 6.7.10. **References:** zlib (Python `zlib`), `lz4` 1.10.0, `xz` 5.8.3/5.8.4
(liblzma 5.8.4 sources), `zstd` 1.5.7, `brotli` 1.2.0 (CLI and libbrotlidec via ctypes), GNU binutils
for the fold's bytes, `qemu-aarch64`.

---

## TL;DR

**2 HIGH · 10 MEDIUM · 19 LOW · 12 INFO. Fixed in 2.8.6: both HIGHs, 9 of 10 MEDIUMs, 16 of 19 LOWs,
4 of 12 INFOs. Each of the rest is pinned to a roadmap release (below).**

- **The two HIGHs are lock and slot bugs, not codec bugs.**
  - C-01: the zip streaming writer kept a byte offset in the slot that has held the writer's allocator
    since 2.7.7, so streaming any member but the first made the next allocation call through that
    offset (into the non-PIE program image for an offset ≥ 4 MiB).
  - C-02: the API lock was an arena pointer created on first use. Threads arriving together after a
    detected `alloc_reset()` each made their own mutex and both ran inside the critical section.
- **The codecs held up under direct attack.** 531,490 Brotli decodes against libbrotlidec with no
  disagreement, 1,359 zstd frames and every xz edge case against the reference CLIs, every guard-page
  placement clean. What they lacked was **strictness**: the LZ4F and xz decoders accepted, as
  successes, streams the references reject (truncated frames, unchecked header checksums and size
  fields, an Index that does not describe the blocks, a range coder that did not finish).
- **The second cluster is the public surface around the codecs**: Huffman builders that wrote shared
  tables without the lock, streaming contexts that released the lock again on a second finish, and a
  DEFLATE decode path ~1,000× slower than zlib on valid streams with 15-bit codes, holding the lock.

Sources: **X** xz-encoder review, **Z** zstd-encoder review, **B** Brotli-decoder review, **R** runtime
review, **E** CRC-fold review, **D** DEFLATE review, **P** this pass (external research and the
earlier closeout bites).

## Verification

- **Full local CI** (lint, fmt, vet, all 12 bundles regenerated, the profile link gate, DCE, the
  kernel-safe `core_smoke`, aarch64 cross-build, 31 suites, the raw-include builds, 9 fuzz harnesses):
  green.
- **Reference differentials** (all scripts under `build/closeout/ext/`, `build/review/`):
  - DEFLATE: 103,000 streams (valid, mutated, random trees zlib's encoder never emits) vs Python zlib,
    batch and streaming: 0 regressions, 0 wrong bytes, 0 batch/streaming differences; the only
    divergence left is trailing data after the final block (by design).
  - LZ4F: 10,377 cases over three seeds vs `lz4 -dc` (7 flag sets incl. `-BD -BX --content-size`,
    truncations, mutations): 0 disagreements beyond the by-design classes; 3,458 of them again with the
    source flush against a `PROT_NONE` page and each accepted frame at an exactly sized guarded `dst`
    (batch + streaming) and one byte short: 0 faults.
  - xz: 3,316 cases vs `xz -dc`: 29 → 0 disagreements; guard-paged likewise: 0 faults. 23 crafted
    container / chunk / dictionary vectors with `xz -d`'s verdicts are in `xz_decompress.tcyr`.
  - Brotli: 531,490 decodes vs libbrotlidec 1.2.0 (seeds from libbrotlienc q0–11, sankoch's encoder,
    the 240-stream corpus, 294,000 structured streams; mutated): 0 disagreements, 0 guard-page faults.
  - zstd: 1,359 frames (levels 1–9, sizes 0–1.3 MB, window edges ±1) decode byte-identically with
    `zstd -d`; every `dst_cap` below the output length fails cleanly against a guard page.
- **Mutation checks**: every new gate in LZ4F (14), xz decode (14), xz encode coverage (6 reviewer
  mutants), the Huffman builders (3), the finish-once guards, the zip slots, the window descriptor,
  `_zo_alloc` and the lock was removed or weakened and seen to fail its test.
- **OOM**: `oom_matrix.tcyr` faults every allocation of 24 round-trip operations (now including a
  level 9 zstd compress) from cold tables, then retries without a reset: 0 crashes, 0 failed retries.

## External research

- **RFC errata**: nothing new since July for RFC 1950 / 1951 / 1952 / 7932 / 8878. RFC 7932 erratum
  6977 (an implicit distance does not touch the distance block count) was already implemented (2.8.0).
- **zlib** 1.3.2 (Feb 2026; CVE-2026-22184 `untgz`, CVE-2026-27171 `crc32_combine`) was assessed in
  July: not applicable. **lz4** 1.10.0, **zstd** 1.5.7, **brotli** 1.2.0: no new releases.
- **xz 5.8.4** (2026-09-09): GHSA-5qpq-xqfv-j9pg (invalid access when a decoder is reused after an
  allocation failure) is the class `oom_matrix.tcyr` sweeps; the `lzma_index_cat` slowdown does not
  apply (sankoch decodes concatenated streams independently, linearly). Reading liblzma 5.8.4's
  `lzma2_decoder.c` / `lz_decoder.c` against sankoch's decoder is what produced C-15 to C-18.
- **lz4_flex CVE-2026-32829** (match offsets not validated): not applicable (`offset > dp - lo` is
  checked). Reading the LZ4 frame specification against the decoders produced C-03, C-13, C-14.

## Coverage, reviewed as a matrix

The 2.7.14 and 2.8.0 lessons were that coverage gaps hide in combinations (rich alphabet × streaming,
roomy buffers × over-writes). This pass's matrix, with the cells it filled:

| | batch | streaming, small chunks | guard-paged src | exact guarded dst | OOM sweep | reference oracle |
|---|---|---|---|---|---|---|
| DEFLATE / zlib / gzip decode | ✓ | ✓ (rich trees, 1–64 B chunks) | — | — | ✓ | ✓ zlib |
| LZ4F decode | ✓ | ✓ (1–97 B) | ✓ new | ✓ new | ✓ | ✓ new `lz4 -dc` |
| xz decode | ✓ | n/a | ✓ new | ✓ new | ✓ | ✓ new `xz -dc` |
| xz encode | ✓ (> window, multi-chunk, > 2 MiB new) | n/a | — | ✓ | ✓ | ✓ `xz -d` (local) |
| zstd encode | ✓ | n/a | — | ✓ | ✓ (L9 new) | ✓ `zstd -d` (local) |
| Brotli decode | ✓ | n/a | ✓ | ✓ | ✓ | ✓ libbrotlidec |
| Huffman builders / streaming lifecycle | ✓ | ✓ (threads, double finish new) | — | — | ✓ | n/a |

Gaps left, all on the roadmap: DEFLATE-family decoders are not yet run against guard pages in CI (the
fuzzers place Brotli only), and the reference oracles for LZ4F / xz / zstd run locally, not in CI (no
Python or reference CLI there by policy).
