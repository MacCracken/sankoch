## TL;DR

**Zero HIGH / MEDIUM / LOW findings.** The 2.2.4 fmt pass, 2.2.5
`: i64` return-type annotation pass, and 2.2.6 Cyrius 6.0.1 + aarch64
binary-rename patch landed clean: every gate green, every prior
audit fix verified intact, every test passes byte-for-byte, every
SIZE wire-format line unchanged from the 2.2.3 baseline. Cleared to
open 2.3.0.

Three INFO observations from 2026-05-01 still apply, all carried
forward unchanged (no consumer signal to act on any of them yet):

- **INFO-A** — 35 lazy-global alloc sites still abort on first-call
  OOM. Deferred; would need error propagation through internal
  callers. Realistic OOM victim is the per-call ctx alloc, which
  2.2.1 hardened.
- **INFO-B** — `*_decompress_dict` requires `dst_cap >= dict_len`.
  Already enforced at runtime; docstring polish item.
- **INFO-C** — aarch64 LZ77 8-byte word-compare uses unaligned
  `load64`. ARMv6+ permits it; some implementations pay a
  cycle-count penalty vs aligned. Flagged for future investigation
  if aarch64 perf benchmarks ever surface this section as hot.

## Cyrius 5.7 → 6.0 stdlib API drift

Quick survey of the stdlib surface sankoch depends on (`syscalls`,
`string`, `alloc`, `fmt`, `vec`, `fnptr`, `thread`, `assert`):

- Build resolves every symbol clean against 6.0.1. The 5.10.x REAL
  TYPE SYSTEM and 5.11.x annotation arc landed without breaking any
  signature sankoch consumes — the 2.2.5 pass was the response on
  our side (every public fn in `src/*.cyr` got `: i64`).
- 5.7.48 → 5.8.64 introduced no public-API change visible from
  sankoch (covered by 2.2.4).
- `cc5_aarch64` → `cycc_aarch64` rename at 6.0 is the only
  workflow-level break, fixed in 2.2.6.
- No new stdlib module sankoch depends on (we do not consume
  `sandhi` HTTP/service from 5.7+).

## Decision

**Cleared to open 2.3.0** — true incremental decompression. Treat
as large per CLAUDE.md task-sizing; DEFLATE state-machine
suspension lands first in its own bite, with `deflate_dec_*` round-
trip tests covering at least: small inputs, inputs that straddle
chunk boundaries at every interesting state-machine junction
(block-header, code-length parse, lit/dist code, length-extra,
distance-extra, stored-block raw copy mid-chunk), bad input
returns negative without consuming input the caller can recover.
zlib/gzip wrappers and LZ4F follow once DEFLATE is stable.
