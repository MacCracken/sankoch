# Sankoch State

> **Last refresh**: 2026-08-24 (v2.7.10 cut — **surviving a caller's `alloc_reset()`**. Closes a chitra consumer report filed as "calling `alloc_reset()` between decodes breaks the next PNG decode"; the decode error was the benign symptom and the defect is a **wild write**. Every lazy global in this library is a raw pointer into the stdlib bump arena memoized behind an `if (ptr == 0)` guard — the CRC-32 table, the Huffman tables, the LZ77/LZ4 hash tables, and **`_sankoch_mtx` itself** — and `alloc_reset()` rewinds that arena without telling anyone, so every one of them goes dangling while staying non-zero. Measured at this library's own boundary against 2.7.9: a caller that allocated 32 KB after the reset and made **one ordinary `crc32_init_table()` call** had **16,351 of its own bytes overwritten**, and a zlib round-trip after a reset returned `clen = -2, dlen = -1` and kept failing. The detection is **exact, not heuristic**: `alloc_reset()` already **zeroes the span it rewinds** (its own info-leak mitigation), so an arena-allocated canary stamped with a magic reads back as zero afterwards — one load and one compare, checked at the top of `_sankoch_lock()` *before `_sankoch_mtx` is touched* and again inside `crc32_init_table()`, which consumers call directly without the lock. When it fires the existing `_sankoch_reset_tables()` (no longer test-only) drops every memoized pointer and the canary re-arms. Also made **`crc32_init_table()` idempotent** — it allocated once but **rebuilt the 16 KB table on every call**, which is both why a per-decode consumer was wasting the work and what drove the wild write. New `tests/tcyr/arena_reset.tcyr` (21 assertions, all of which fail against 2.7.9: caller memory intact, CRCs still *correct* afterwards — detection must rebuild, not merely decline to write — a full public-API round-trip across two resets, and eight consecutive resets to prove the guard re-arms). No public API or format behaviour changed; a caller that never resets pays one load and compare per API entry. 4,495,243 assertions / 0 failures across **25** suites; 6 fuzz harnesses / 0 failures; ten dist bundles regenerated; aarch64 cross-build + core smoke green. ## In-flight slots

**2.7.9 shipped — the DEFLATE encoder gained a sync flush, and a block-type chooser it forced.**
A consumer filing (bote, RFC 7692 `permessage-deflate`) asked only for exposure — the flush
machinery already existed, `_dyn_flush_subblock(bw, bfinal)` having always taken the flag. What
the filing could not know is that exposing it made a long-standing simplification expensive:
the level >= 4 path emitted BTYPE=10 unconditionally, which is free across a 16 K-symbol batch
sub-block and ruinous when a flush closes a sub-block per message. Pricing dynamic against fixed
(as zlib always has) took the RFC 7692 framing from +64 % over the reference to +0.1 %, and
improved three batch SIZE rows as a side effect. **The lesson worth carrying: the consumer's ask
was the cheap half; the measurement after shipping it was where the real work was.**

**2.7.5 shipped — the encoder ladder is complete.** Six releases closed the largest encoder gaps
in the tree. The **xz** encoder (2.7.0–2.7.2): repetitive-data speed (rep-only `nice_len` shortcut,
~290–473×), real-source speed (BT4 binary-tree finder, +21 %; an HC4 attempt was rejected — the
"78 % match finder" was operation-count, not time), real-source ratio (xz-private window 32 KB →
256 KB, now within ~0.2 % of `xz -6`). The **zstd** encoder (2.7.3–2.7.5): a DP optimal parser at
levels 7–9 with per-block best-of, then a **cross-block match window** (both parses lifted to
frame-global coordinates + a persistent 512 KiB window) — sankoch's zstd now **beats `zstd -19` on
record data** (L9 −44.7 %) and improves source −10.5 %, with single-block output byte-identical and
no frame/offset change (single-segment frames make any distance decodable) — then a **hash-chain
saturation cutoff** (2.7.5) that reclaimed the repetitive-record L9 cost the frame-global chain had
introduced (record L9 2.76 → 1.86 s, ratio Δ ≤ +0.043 %). DEFLATE's shared lz77 stayed frozen
throughout. Every release was research-backed and adversarially reviewed via a workflow before code
landed, and each shipped as sequential verified bites (2.7.4 was 5 bites).

**▶ 2.8.x scheduled — two backlog items taken down, then a P(-1) closeout (opens straight to the
feature; no P(-1) lead).** The forward ladder in [`roadmap.md` § Scheduled](roadmap.md#-scheduled--28x) is:
**2.8.0 = SIMD CRC-32 via `PCLMULQDQ`** (an x86 fold beyond the wire-identical slice-by-8 already
banked at 2.3.4 [~2×]; needs an aarch64 PMULL path or scalar fallback, and must clear a
silent-corruption bar), then **2.8.1 = GPU texture compression** (BC1–BC7 / ASTC — the one lossy,
GPU-format-specific codec; first sub-step is the home decision, sankoch vs mabda), then a
**P(-1) hardening pass at the end of the 2.8.x line** — the un-audited 2.7.x encoder surface (BT4
`son[]`, the 4 MiB frame-global chain, DP-optimal arrays, window/cutoff math) audited together with
the 2.8.0/2.8.1 additions (the hand-assembled `PCLMULQDQ` fold, the GPU block encoder) before the
next minor opens; it ships as its own release, as the 2.6.4 ZIP-surface audit did. Remaining
**Backlog (unscheduled)**: a wire-identical DEFLATE match-finder speedup (byte-for-byte-parity
mandate blocks the obvious knobs) and the Brotli codec (gated on a web/font consumer).
