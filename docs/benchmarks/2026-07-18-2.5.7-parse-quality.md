## What moved since 2.5.6

At 2.5.6 the encoder was roughly at `zstd -1` parity (−2 % to +7 %). At 2.5.7 it **beats
`zstd -1` by 6–16 % and `zstd -3` — zstd's *default* level — by 4–11 %** on real
code/text/binary. The two items:

- **Repcode-aware matching** (bite 1): modest on its own (~1.4 % on repeat-heavy data;
  ~52 % of sequences now encode as repeat codes) but composes with the FSE tables — an
  all-repcode offset stream becomes an RLE OF table (0 offset-code bits).
- **Adaptive FSE sequence tables** (bite 2): the headline. The Predefined LL/OF/ML tables
  are tuned for *typical* distributions; real blocks are skewed enough that a table fitted
  to the block's histogram wins decisively. Structured/tabular data — where the Predefined
  tables were worst — collapsed from **+106 % → −6 %** vs `zstd -1`.

Per-block, each stream is planned independently: **RLE** (1 distinct code → 1-byte
description, 0 bitstream cost), **FSE_Compressed** (histogram-fitted table, chosen only
when it beats Predefined *including* its exact `writeNCount` size), else **Predefined**.
The interleaved backward bitstream flushes each state with its own accuracy log.

## Remaining gap

Very regular record data (a synthetic csv: +45 %; a synthetic log line: +104 %, though
only 691 vs 338 B absolute) still trails `zstd -1`. That residue is *match quality* — zstd's
optimal parse finds longer cross-record matches than a greedy+lazy+repcode hash chain. A
small optimal / 2-pass parse is the future item; it is niche relative to the code/text/
binary wins above.

## Correctness & cost

- **108/108** files × sizes (500 B … 300 K, across many inputs) decode byte-identical via
  reference `zstd -d`, exercising RLE / FSE_Compressed / Predefined mode mixes; plus the
  13-case encode smoke and the fuzz round-trips.
- Encode throughput ~8 MiB/s worst-case (level 6, low-redundancy input); the repcode
  search + per-block FSE planning add ~15 % over 2.5.6. The 1..9 level knob trades this.
- **No wire-format SIZE gate for zstd** — encoder output is not bit-reproducible across
  encoder versions; the `SIZE zstd6_*` bench lines are informational.
