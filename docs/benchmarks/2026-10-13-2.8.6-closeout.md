# 2.8.6 — the 2.8.x-closeout P(-1) pass

**Date**: 2026-10-13 · **Machine**: x86_64 linux (Ryzen 7 5800H, PCLMULQDQ) · **Toolchain**: Cyrius 6.7.10 ·
**Prior doc**: [`2026-10-13-2.8.5-crc32-pclmul.md`](2026-10-13-2.8.5-crc32-pclmul.md)

2.8.6 is the hardening pass ([audit dossier](../audit/2026-10-13-2.8.x-closeout.md)). Two `cyrius bench`
runs of the tree on one idle machine: the **baseline** at the start of the pass (the 2.8.5 code) and the
**post-review** run after every fix. ns/op are machine-local; compare them within this file.

## SIZE: 49 rows, unchanged

Both SIZE blocks are identical. No fix in this pass changes what an encoder writes for these inputs.
(The zstd Window_Descriptor, C-10, adds one byte only to frames larger than the 512 KiB window; no
bench input is.)

## Speed: no row moved

Every row is within run-to-run noise of the baseline. The two rows outside ±10 % are noise:
`adler32 4KB text` (code this pass does not touch) ranged 6,364–7,959 ns over three further runs, and
`lz4f c text 128K` 745,788–751,106 ns. The decoders the pass rewrote kept their speed on the bench's
inputs: `lz4 d text 4K` 10,524 → 10,207 ns (the block core is shared with LZ4F linked blocks now),
`deflate d text 4K` 15,617 → 14,814–15,364 ns (the Huffman slow path only runs for codes longer than 9
bits, which the bench's streams do not use).

## Where the pass did change speed

Not on the bench's inputs, by design: the DEFLATE fix (C-07) changes inputs whose codes are longer than
9 bits.

| Input | 2.8.5 | 2.8.6 | Python zlib |
|---|---:|---:|---:|
| valid 937,655 B stream, one dynamic block, a 15-bit literal code (500,000 B out) | 3.42 s | 0.155 s | 3.2 ms |
| 50,000 literals on 15-bit codes, relative to the same on 1-bit codes (thread CPU) | 126× | 6.6× | — |

The second row is what `deflate_decompress.tcyr` now bounds (40×).
