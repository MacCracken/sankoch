# 2.8.0 — Brotli decode throughput baseline

**Date**: 2026-09-16 · **Machine**: x86_64 linux (Ryzen 7 5800H) · **Toolchain**: Cyrius 6.6.4 ·
**Prior doc**: [`2026-09-07-2.7.12-toolchain-verify.md`](2026-09-07-2.7.12-toolchain-verify.md)

2.8.0 adds a Brotli decoder (RFC 7932) and changes no encoder. This file records the first Brotli
decode baseline and confirms that the wire-format SIZE table did not move.

## How to read this file

`ns/op` and MB/s come from one `cyrius bench tests/bcyr/sankoch.bcyr` run on the release tree, taken
after the closeout gates on an otherwise idle desktop. They are a machine-local baseline for spotting
regressions, not a cross-machine claim. MB/s is decoded output per second.

## Brotli decode (new rows)

| Row | Input | Output | ns/op | MB/s |
|---|---:|---:|---:|---:|
| `brotli d text q11 152K` | 50,096 | 152,089 | 1,336,317 | 113.8 |
| `brotli d text q5 32K` | 12,684 | 32,768 | 350,905 | 93.3 |
| `brotli d font q11w22 401K` | 169,278 | 410,820 | 4,940,772 | 83.1 |
| `brotli d zeros 256K` | 13 | 262,144 | 44,736 | 5859.7 |
| `brotli d stored 10K` | 10,004 | 10,000 | 2,461 | 4063.3 |
| `brotli d records 68K` | 11,206 | 68,000 | 405,096 | 167.8 |

Fixtures, all under `tests/data/brotli/` except the font:
- `text q11 152K`: google `alice29.txt.compressed`;
- `text q5 32K`: the first 32,768 B of alice29 at `-q 5 -w 16`;
- `font q11w22`: `brotli -q 11 -w 22` of LiberationSans-Regular (410,820 B), the WOFF2-shaped
  stream, read from `build/brotli-smoke/font.q11w22.br`, which `scripts/brotli-smoke.sh` writes;
- `zeros`: google `zeros.compressed`, 13 B that expands to 256 KB;
- `stored`: google `random_org_10k.bin.compressed`, uncompressed meta-blocks;
- `records`: `bswitch_records_68k.q11w16.br`, block switching over record data.

Where the time goes: the command loop with context-map literals dominates `text` and `font`.
`zeros` and `stored` measure the word-wise overlapping copy and the uncompressed path.

**Adversarial IMTF** (`tests/tcyr/brotli_decompress.tcyr` T12, not a bench row): the 76-byte
`adv_imtf_256_trunc` forces 16,384 x 255 list moves before failing. It decodes at about **19 ms per KB
of input**, **0.19x** the bytewise reference IMTF's CPU time. The suite asserts the ratio (<= 0.5), not
the absolute figure.
