**Date**: 2026-07-19 · **Machine**: x86_64 linux · **Toolchain**: Cyrius 6.4.67 ·
**Reference**: `zstd` CLI v1.5.7 (Yann Collet)

The 2.5.8 slot was scheduled as an optimal / 2-pass parse. Diagnosis found the residue was
not missing search depth — it was the parser comparing raw match **lengths** where it
should have compared encoded **cost**. **Every output below was decoded byte-identical by
reference `zstd -d`** — the correctness bar. Sizes are frame bytes at the default level.

**278,970 → 251,333 B, −27,637 B (−9.9 %)**.

**Every one of the eleven fixtures is at or below its 2.5.7 size.** There is no regression
anywhere, including on incompressible input and on inputs already at their optimum.

sankoch's default level now **beats `zstd -3` — zstd's own default — on every fixture**.
At 2.5.7 it still lost to `-3` on json records (+12.1 %) and ascending integers (+34.2 %).

## What moved

Four changes, each measured in isolation on the seven-fixture corpus:

| # | change | corpus delta | deflate + bash |
|---|--------|-------------:|---------------:|
| 1 | Huffman tree description race (direct vs FSE weights) | −331 B | 0 B |
| 2 | **priced lazy accept test** (`_ze_mvalue`) | **−17,995 B** | −210 B |
| 3 | **repcode candidates at the lookahead position** | **−6,981 B** | **−697 B** |
| 4 | delete the `+2` rep slack; price rep-vs-regular at `pos` | −366 B | −105 B |
| 5 | rep0−1 probe (RFC 8878 parity) | −93 B | −15 B |
| 6 | rep-locked lookahead (repcode may only yield to a repcode) | −1,871 B | +9 B |
| | **total** | **−27,637 B** | **−1,018 B** |

Change 2 is 65 % of the release; change 3 is the largest real-data contributor.

Change 6 is the one step that costs real data, and only barely: +9 B on `/bin/bash`
(+0.006 %) against −1,871 B on the corpus. The unrestricted form of it — letting *any*
candidate displace a repcode — was measured at −2,060 B corpus for **+47 B** on bash, and
was rejected: locking the displacement to repcode → repcode keeps 91 % of the win for 19 %
of the real-data cost. Even including it, bash finishes the release 936 B *smaller* than
2.5.7.

## The defect this release fixes

On ascending decimal integers, merely enabling the one-step lookahead made output **67 %
bigger**:

| level | 2.5.7 | 2.5.8 |
|-------|------:|------:|
| 1 (greedy) | 21,337 | 21,266 |
| 2 (lazy) | **35,710** | **13,896** |
| 6 (default) | 35,825 | 14,424 |

The repeat-code share of the sequence stream collapsed from 90 % to 42 %. The accept test
compared raw lengths, so a one-byte-longer match at a fresh 16-bit offset outranked a
repeat code — and broke the repcode run that let the offset stream encode as an RLE table.
`test_zc_lazy_beats_greedy` now asserts the lazy levels never lose to greedy; 2.5.7 fails it.

## Why not the DP

The scheduled optimal parse was built and measured side by side before being deferred:

| metric | 2.5.7 | **this release** | verified DP probe |
|--------|------:|-----------------:|------------------:|
| 7-fixture corpus | 278,970 | **251,333** | 251,733 |
| deflate + bash | 168,309 | 167,291 | **164,055** |
| encode cost | 1.0× | **1.1–1.4×** | 4–74× |
| new allocation | — | **0 bytes** | ~224 KiB |
| source added | — | **~100 lines** | ~400 lines |

The priced parse **beats the DP on total corpus size** at a fraction of the cost. The DP is
genuinely better on real source/binary specifically (−3.6 % against this release's −0.5 %),
which is why it stays on the roadmap as its own arc rather than being discarded.

## Benchmark coverage gap closed

The three `SIZE zstd6_text_*` bench lines use a periodic filler that is one long match at
any level. They did not move by a single byte across *either* the 2.5.7 or the 2.5.8 parse
rewrite — `bench` was blind to parse quality. The new `SIZE zstd6_rec_256K` line uses
records whose body recurs at an offset that drifts by one per record:

```
SIZE zstd6_rec_256K 262144 7846      # 2.5.7
SIZE zstd6_rec_256K 262144 5278      # 2.5.8   (−32.7 %)
```

## Correctness & cost

- **15/15** encode-smoke cases decode byte-identical via reference `zstd -d` v1.5.7,
  including two new fixtures (`hjsonrec` drifting-offset json records, `hasc` ascending
  integers) added for the shapes this release targets.
- `cyrius test` — all suites green, 0 failures. `zstd_compress.tcyr` 135 assertions
  (was 123; +2 regression tests).
- `cyrius fuzz` — 5/5 harnesses PASS, including `fuzz_zstd`'s 1,150 iterations
  (400 random-input + 600 encode round-trip + 150 corruption).
- **Wire-format SIZE gate unmoved** — all 46 pre-existing `SIZE` lines byte-identical.
- Encode wall-clock 1.08–1.40× on the encode driver (measured over the fixtures above;
  includes process startup and file I/O, so the encode-only ratio is somewhat higher). The
  cost is one extra `_ze_rep_search` — three byte-compares — per lookahead.
- **No new allocation.** The release adds no arrays and no globals beyond one price function.

## Known limitation

Deeper levels remain slightly non-monotonic on some inputs (csv is best at level 6, not 9;
spread under 2 %). This is inherent to greedy+lazy parsing — a longer match found by a
deeper search is not always globally better — and needs the DP to fix properly. The gross
2.5.7 inversion is gone and is now covered by a test.
