# Sankoch 2.3.8 — Pre-2.4.0 P(-1) Baseline

**Date:** 2026-06-16
**Toolchain:** Cyrius 6.2.15 (manifest-pin)
**Hardware:** x86_64 Linux 7.0.11-arch1-1
**Bundle:** dist/sankoch.cyr (6709 lines)
**Purpose:** Reference baseline at the 2.3.x closeout, immediately before
the 2.4.x decode-only xz/bzip2 (takumi-driven) arc opens. Every SIZE line
below is the wire-format gate going forward — must stay byte-for-byte
identical across patch/minor releases unless a `Breaking` CHANGELOG entry
says otherwise. Captured during the 2.3.8 P(-1) sweep
(`cyrius bench tests/bcyr/sankoch.bcyr`).

---

## Checksums

| Op                | len    | ns/op   |
|-------------------|--------|--------:|
| adler32 4KB text  | 4096   |  ~9,000 |
| crc32   4KB text  | 4096   |  ~5,550 |
| adler32 1KB text  | 1024   |  ~1,560 |
| crc32   1KB text  | 1024   |  ~1,385 |
| adler32 256K text | 262144 | ~394,000 |
| crc32   256K text | 262144 | ~335,000 |

CRC-32 remains **faster than Adler-32** at steady state (the 2.3.4
slice-by-8 win holds: crc32 256K ≈ 335k ns vs adler32 ≈ 394k). 4KB has
high run-to-run variance; the 1KB / 256K figures are the reliable ones.

## Representative throughput (ns/op)

| Op                          | in     | out  | ns/op     |
|-----------------------------|--------|------|----------:|
| lz4 c text 1K               | 1024   | 59   |    ~9,800 |
| lz4 c text 4K               | 4096   | 71   |   ~16,300 |
| lz4f c text 128K            | 131072 | 647  |  ~711,000 |
| deflate L6 text 4K          | 4096   | 71   |  ~152,000 |
| stream deflate L6 text 128K | 131072 | 440  | ~2,324,000 |

No throughput regressions vs the 2.3.4 baseline — 2.3.5/2.3.6/2.3.7 were
decode-capability + robustness work on cold paths (gzip FHCRC,
concatenated members, FDICT, alloc-fail propagation), none on the
encode hot loop.
