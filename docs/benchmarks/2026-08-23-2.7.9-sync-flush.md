# 2.7.9 — DEFLATE sync flush + fixed-vs-dynamic block pricing

**Date**: 2026-08-23 · **Machine**: x86_64 linux · **Toolchain**: Cyrius 6.5.35 ·
**Reference**: Python 3 `zlib` (raw DEFLATE, `wbits=-15`) ·
**Prior**: [`2026-07-21-2.7.4-zstd-window.md`](2026-07-21-2.7.4-zstd-window.md)

2.7.9 exposes `deflate_enc_flush` — the RFC 7692 `permessage-deflate` sync flush — and,
because measuring it immediately exposed the cost, changes how the level ≥ 4 path chooses
a block type. Through 2.7.8 `_dyn_flush_subblock` always emitted BTYPE=10; a dynamic
Huffman header is noise across a 16 K-symbol sub-block, but a sync flush closes a
sub-block **per message**, so a ~60-byte WebSocket frame shipped a ~70-byte header to
describe itself. The encoder now prices dynamic against fixed and emits the cheaper block,
which is what reference zlib has always done.

## The headline — RFC 7692 framing vs reference zlib

Corpus: 31,980 bytes of repetitive JSON-RPC (400 lines), framed the RFC 7692 §7.2.1 way —
compress, sync flush, strip the trailing `00 00 FF FF` — over a single never-terminated
stream (context takeover on). Totals are the sum of the frame payloads, excluding the
harness's 4-byte record prefixes. Both sides at level 6.

| message size | sankoch 2.7.8 (always-dynamic) | **sankoch 2.7.9** | reference zlib | 2.7.9 vs zlib |
|-------------:|-------------------------------:|------------------:|---------------:|--------------:|
| 200 B  | 4,764 | **2,908** | 2,905 | **+0.1 %** |
| 1000 B | —     | **2,415** | 2,415 | **+0.0 %** |
| 4000 B | —     | **1,885** | 1,883 | **+0.1 %** |

At 200-byte messages that is **4,764 → 2,908 bytes (−39.0 %)**, closing a **+64 %** gap
against the reference to **+0.1 %**. The 2.7.8 column is the always-dynamic encoder
measured before the pricing change; the other two rows were not measured against it.

Reference-decoded both directions by `scripts/deflate-flush-smoke.sh`:
`zlib.decompressobj(-15)` accepts every sankoch frame at levels 1 and 6, and sankoch's
streaming decoder reproduces Python's `Z_SYNC_FLUSH` frames byte-for-byte.

⚠ Sync flush costs ratio by construction — each flush forces a block boundary that matches
cannot cross. The same corpus compressed as one un-flushed stream is 1,819 bytes at level 6.
That gap is RFC 7692's, not sankoch's, and it is why the table's ratio improves with message
size.

## Batch path — no regression

The pricing change is shared with the batch compressor, so the gated SIZE lines are the
control. Every row is unchanged except three, all improvements:

| fixture | 2.7.8 | 2.7.9 | Δ |
|---|---:|---:|---:|
| `deflate6_text_1K` | 58 | **55** | −3 |
| `zlib6_text_1K`    | 64 | **61** | −3 |
| `gzip6_text_1K`    | 76 | **73** | −3 |
| all 40 other SIZE rows | — | — | **0** |

Only the 1 K rows move: at 4 K and above the header already amortises and dynamic keeps
winning, which is the expected shape. The chooser can never inflate a block — it emits
fixed only when `fix_bits <= hdr_bits + dyn_bits`.

## Throughput cost

Pricing the header means writing it into a scratch bitwriter before deciding, i.e. one
extra header write per sub-block. That is O(hlit + hdist), not O(symbols), so it lands
entirely on small blocks:

| benchmark | 2.7.8 (ns/op) | 2.7.9 (ns/op) | Δ |
|---|---:|---:|---:|
| `deflate L6 text 4K` | 142,023 | 146,612 | +3.2 % |
| `deflate c text 4K`  | 142,019 | 146,236 | +3.0 % |
| `zlib c text 4K`     | 148,157 | 152,289 | +2.8 % |
| `deflate L9 text 4K` | 143,746 | 147,115 | +2.3 % |
| `deflate c rand 4K`  | 392,265 | 394,718 | +0.6 % |
| `stream deflate L6 text 128K` | 2,083,908 | 2,073,783 | −0.5 % |
| `gzip c text 4K`     | 160,239 | 160,027 | −0.1 % |

~3 % on 4 KB batch compresses, nil on the 128 KB streaming path where the header amortises.
Accepted deliberately: it buys −39 % on the flush path and −5 % on 1 KB batch output, and it
is bounded by block count rather than input size.

## Method

- `cyrius bench tests/bcyr/sankoch.bcyr`, same machine, back-to-back runs.
- Framing totals from `scripts/deflate-flush-smoke.sh` with `MSG_SIZE` swept over
  200 / 1000 / 4000; reference figures from `zlib.compressobj(6, DEFLATED, -15)` +
  `flush(Z_SYNC_FLUSH)` on the identical corpus and identical message split.
- ns/op figures are single-run and carry the usual few-percent noise; the three ~3 % rows
  are reported as a consistent direction across four independent small-input benchmarks,
  not as a precise figure.
