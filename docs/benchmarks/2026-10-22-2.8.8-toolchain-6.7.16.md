# 2.8.8 — toolchain move: cyrius 6.7.10 → 6.7.16

**Date**: 2026-10-22 · **Machine**: x86_64 linux (Ryzen 7 5800H, PCLMULQDQ) · **Toolchain**: Cyrius 6.7.10 →
6.7.16 · **Prior doc**: [`2026-10-13-2.8.6-closeout.md`](2026-10-13-2.8.6-closeout.md)

2.8.8 changes no source. Two `cyrius bench tests/bcyr/sankoch.bcyr` runs of the same tree (the 2.8.7
code) on one machine, back to back: the **baseline** on the 6.7.10 pin, then the **move** on 6.7.16
after `cyrius deps` re-vendored `lib/`. cyrius re-execs into the pinned toolchain, so each run used its
own compiler and its own `lib/`. ns/op are machine-local; compare them within this file.

## SIZE: 47 rows, identical

Both SIZE blocks are byte-identical (`diff` of the `SIZE` lines is empty). The encoders write the same
bytes under either compiler.

⚠ **Counting note.** The bench prints 47 `SIZE` rows between a `--- SIZE comparison ---` and an
`--- END SIZE ---` line. 2.8.4 reported 47. The 2.8.6 doc and CHANGELOG said 49, because `grep -c SIZE`
counts the two marker lines. No row was added between 2.8.4 and 2.8.6. Count with `grep -c '^SIZE '`.

## Speed: no row moved

68 rows; the ratio 6.7.16 / 6.7.10 has a geometric mean of **1.004** (min 0.893, max 1.072). One row
is outside ±10 %: `adler32 4KB text`, 7,586 → 6,777 ns. The 2.8.6 doc already measured that row
moving 6,364–7,959 ns between runs of unchanged code, so it is noise, not a toolchain effect.

## Binary size

`src/lib.cyr` built as CI builds it (`CYRIUS_DCE=1`): 190,328 → **186,232 B** (−4,096). Without DCE:
710,520 → 702,328 B (−8,192). The compiler counts 897 → 900 unreachable functions in the non-DCE
build.
